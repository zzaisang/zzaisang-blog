## 왜 만들었나

가족 단위 소비는 한 사람이 기록해서는 잘 안 맞는다. 누가 무엇을 샀는지, 매달 나가는 고정비가 얼마인지, 사려던 물건을 정말 사도 되는지가 흩어져 있다. **현소는 "현명한 소비"를 가족이 함께 하도록 돕는 앱**이다.

## 내가 한 일

기획부터 iOS 앱, 백엔드, 관리자 웹, 출시·운영까지 혼자 맡았다. App Store 에 출시한 뒤 1.0.x 업데이트를 이어 가고 있다.

## 주요 기능

- **홈 대시보드**: 가족의 소비 흐름을 한 화면에 보여준다.
- **가계부·수입·고정비용**: 지출과 수입, 매달 나가는 돈을 기록한다.
- **우리집 자산**: 가족의 자산·부채를 기록하고 시점별 합계를 본다.
- **구매 검토**: 사기 전에 가족과 함께 검토하고, 구매·보류 결과를 남긴다. 사진도 붙일 수 있다.
- **입력함**: 사진·공유 시트·위젯·Siri·단축어로 넣은 내용을 AI 가 초안으로 정리하고, 사용자가 확인한 뒤 저장한다.
- **알림함·푸시**: 고정비 납부일, 구매 검토 요청 같은 알림을 보낸다.
- 이메일·카카오·Apple 로그인, 가족 초대.

## 기술 선택과 이유

- **Flutter + Riverpod + go_router.** 한 코드로 앱을 만들고, 개발 중에는 웹(Chrome)으로 빠르게 확인한다. 배포는 iOS 만 한다.
- **Supabase (PostgreSQL + RLS).** 가족 단위로 데이터를 나누는 일을 DB 의 행 수준 보안(RLS)에 맡겼다. 서버 코드를 따로 두지 않아도 된다.
- **Edge Function + pg_cron 으로 푸시 발송.** 알림 조건 판단을 DB 가까이에 두고, FCM 으로 보낸다.
- **사진은 Cloudflare R2.** Edge Function 이 presigned URL 만 발급하고, 앱이 직접 올린다. 서버가 파일을 중계하지 않는다.
- **AI 는 초안까지만.** 입력함의 AI 결과는 바로 저장하지 않고, 사용자가 확인한 뒤 반영한다.
- **강제 업데이트.** 최소 지원 버전을 DB 설정으로 관리해, 옛 버전을 앱 배포 없이 막을 수 있다.

## 배운 점과 다음 계획

혼자 운영하려면 **출시 과정 자체를 자동화**해야 했다. 출시 전 E2E 체크리스트, TestFlight 업로드, 스토어 제출을 스크립트와 정해진 절차로 묶어 두었다. 스테이징 없이 운영 DB 하나만 두기 때문에, 마이그레이션을 파일로 남기고 적용 결과를 확인하는 습관이 중요했다.

소스는 비공개다. 앱 소개는 위 링크의 소개 페이지에서 볼 수 있다.
